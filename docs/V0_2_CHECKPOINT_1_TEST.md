# v0.2 Checkpoint 1 — Campaign Creation Test

This checkpoint converts the foundation-only New Promotion screen into a real Koha-native campaign creation workflow.

## Scope under test

- Writable campaign creation form
- Promotion type and channel
- Start/end dates and status
- Optional Koha library, target audience, language, location and notes
- Barcode paste/scan input
- Barcode validation against live Koha items
- Invalid barcode blocking
- Duplicate barcode de-duplication and warning
- Transactional campaign + item + audit writes
- Dashboard campaign/item counts and recent-campaign table
- Core Koha CSRF middleware
- Core Koha plugin `tool` permission

## Development-environment procedure

Use the existing `kohadev` KTD instance and the mounted local plugin repository. Do not use the disposable `kpztest` environment for this checkpoint.

1. Fetch the feature branch locally and switch to it.
2. Restart/reinitialize the plugin inside `kohadev` so Koha sees version 0.2.0 and runs the schema upgrade.
3. Open Promotion & Engagement > New promotion.
4. Create a campaign with no barcodes. It should save successfully.
5. Create a campaign with one known-good Koha barcode. It should save and increment both dashboard counters.
6. Submit one good barcode plus one fake barcode such as `AJSN-NOT-A-REAL-BARCODE`. The campaign must not save and the invalid barcode must be shown.
7. Submit the same valid barcode twice. The campaign should save once, with a duplicate warning, and only one campaign-item row should be written.

## Database verification

Expected schema addition:

```sql
SHOW COLUMNS FROM plugin_ajsn_promo_campaigns LIKE 'channel';
```

Expected campaign rows:

```sql
SELECT campaign_id, campaign_type, channel, name, status, created_by, created_at
FROM plugin_ajsn_promo_campaigns
ORDER BY campaign_id DESC
LIMIT 10;
```

Expected linked item rows:

```sql
SELECT campaign_item_id, campaign_id, itemnumber, barcode, added_by, added_at
FROM plugin_ajsn_promo_items
ORDER BY campaign_item_id DESC
LIMIT 20;
```

Expected audit rows:

```sql
SELECT audit_id, campaign_id, actor_borrowernumber, action_type, entity_type, entity_id, created_at
FROM plugin_ajsn_promo_audit
ORDER BY audit_id DESC
LIMIT 20;
```

## Security expectations

Koha 25.11's plugin runner requires the plugin `tool` permission for the `tool` method. POST submissions use an `op` beginning with `cud-` and include `csrf_token` generated by `Koha.GenerateCSRF`, allowing Koha's core CSRF middleware to validate the request.

## Pass criteria

Checkpoint 1 passes only if:

- valid campaigns save completely,
- invalid-barcode submissions save nothing,
- duplicate item input does not create duplicate campaign-item rows,
- an audit row is created for every successful campaign creation,
- dashboard counts reflect saved data,
- no regression occurs in the existing health endpoint.
